# MeOS

一个从零写起的最小操作系统。当前是**第一阶段**：在 VMware 里用传统 BIOS + MBR
方式引导，进入 32 位保护模式，在图形模式屏幕上居中打印一行中文，然后停机。

```
            Hi，我是meos，很高兴来到这个世界~
```

没有键盘、没有 shell、没有文件系统——这一阶段只证明「引导链路通了、保护模式进了、
显存能画」。

## 怎么构建

需要三样东西，都不大：

- **NASM**（汇编器）—— 装完确认 `nasm` 在 PATH 里
- **Python 3 + Pillow** —— 用来把系统字体渲染成点阵字模，并打包镜像
- **mkisofs** —— 打包 El Torito 可引导 ISO（VMware Workstation 自带一个）

```powershell
.\build.ps1            # 构建
.\build.ps1 -Clean     # 先清空 build\ 再构建
.\build.ps1 -Message "你好"    # 换一行要显示的文字（会重新渲染字模）
```

产物都在 `build\` 下：

| 文件 | 说明 |
| --- | --- |
| `boot.bin` | 引导扇区，恰好 512 字节 |
| `payload.bin` | 内核载荷，被引导扇区装到物理地址 0x8000 |
| `meos.img` | 1.44MB 软盘镜像（BIOS 可直接引导） |
| `meos.iso` | El Torito 可引导光盘镜像，给 VMware 用 |
| `meos.vmx` | 配套的虚拟机配置 |

## 怎么跑

```powershell
.\tools\vmtest.ps1 -Wait 12          # 启动虚拟机、截图、判读日志
.\tools\vmtest.ps1 -Wait 12 -Keep     # 同上，但跑完不关机
```

脚本会把虚拟机控制台窗口临时置顶再截图（桌面上别的窗口会挡住它），
然后去 `vmware.log` 里找 `PANIC`，告诉你虚拟机是活着还是崩了。

## 代码结构

```
src/boot/boot.asm      引导扇区：显示开机提示，用 INT 13h 把内核读进内存，跳过去
src/kernel/kernel.asm  内核：16 位实模式准备环境 → 32 位保护模式画字 → 停机
src/kernel/font.inc    点阵字模，由 tools/genfont.py 自动生成，不要手改
tools/genfont.py       用 Pillow 把系统字体渲染成单色点阵
tools/mkfloppy.py      把引导扇区和内核拼成软盘镜像
tools/vmtest.ps1       启动虚拟机 + 截图 + 判读日志
tools/vmdiag.py        从 .vmem 里读内核写的诊断块
tools/preview.py       把截图转成终端可见的 ASCII 灰度图
vm/meos.vmx            虚拟机配置模板
```

### 引导链路

```
BIOS → 读软盘第 0 扇区到 0x7C00 → 引导扇区用 INT 13h 把内核读到 0x8000
     → 跳 0x8000 → 内核 16 位阶段：开 A20、VBE 选并设置 800x600x32 模式、
       把帧缓冲参数写进参数块、建 GDT、置 CR0.PE → 32 位阶段：
       建 IDT、清屏、居中画字、屏蔽 8259 后 sti+hlt
```

### 内存布局

| 地址 | 用途 |
| --- | --- |
| `0x0000-0x04FF` | 实模式中断向量表、BIOS 数据区（不动它） |
| `0x5000` / `0x5200` | VBE 信息块 / 模式信息块缓冲区 |
| `0x6000` | 参数块：帧缓冲地址、行跨度、分辨率、位深 |
| `0x6200` | 诊断块：执行阶段、SVGA 寄存器、显存自检结果 |
| `0x7000-0x77FF` | 保护模式用 IDT（256 项） |
| `0x7C00` | 引导扇区 |
| `0x8000` | 内核载荷入口 |
| `0x7C000` | 内核栈顶 |
| `0xE8000000` | VBE 线性帧缓冲（由 SVGA_REG_FB_START 确认） |

## 调试手段

这个项目最麻烦的地方在于：屏幕上什么都不显示时，你没法知道是没画上去、
画到别处去了，还是画上去了但没显示出来。所以留了两个后门：

**一、诊断块 + `.vmem`。** 虚拟机运行期间 VMware 会把客户机物理内存映射成
`build\<uuid>.vmem`，文件偏移就等于客户机物理地址。内核把中间结果写进
`0x6200`，宿主机直接读出来：

```powershell
python tools\vmdiag.py
```

```
  阶段    = 5  (显存自检也做完了，已停机)
  SVGA_REG_FB_START        = 0xE8000000
  读写回测 @ 参数块FB      = 0x5A5AA5A5 (可写)
  文字包围盒读回白像素     = 2672  (期望 2672，= 字模置位数) OK
```

**二、显存自检。** 画完之后把显存读回来，数一数文字包围盒里有多少个白像素，
写进诊断块。数字对得上，说明显存里的画是对的，问题只可能在显示刷新；
是 0，说明根本没画上去。这一招能一刀切开两类完全不同的故障。

## 踩过的坑

**1. 参数块读错了地址，把 VMware 写崩了。** 16 位阶段把参数写进 `0x6000`，
但 32 位阶段读的是 `[P_FB]`——而 `P_FB` 只是个偏移量（0x00），
于是实际读的是物理地址 `0x0000` 的**实模式中断向量表**。清屏时拿这套垃圾参数
算出天文数字的长度，`rep stosd` 一口气刷了几百 MB 物理内存，路上正好盖住
VMware 给 SVGA 的 MMIO 空间，虚拟机当场报
`iospace_shared.h:479 VERIFY` 不可恢复错误。
**教训：跨阶段共享的结构，访问时必须写全基址。**

**2. `shl eax, 1` 取不到字节的最高位。** 画点阵时用 `shl` 把像素位移进进位标志，
写成 `shl eax, 1` 的话进位来自 bit31，而 `EAX` 只有 8 位有效数据，
结果一个像素都不会画。必须是 `shl al, 1`。
**教训：操作数是几位，就用几位的移位。**

**3. 保护模式没有 IDT 就是三重故障。** 异常没人接 → 三重故障 → VMware 直接复位
虚拟机，现象和「虚拟机自己重启了」一模一样，极难排查。内核里装了一张
256 项全指向同一个兜底处理程序的 IDT，出事至少能停在原地。

**4. `cli; hlt` 会让 VMware 判定「客户机操作系统已禁用 CPU」。**
先把 8259 的中断全屏蔽，再 `sti`，CPU 才能真正安静地歇在 `hlt` 上。

**5. 截图截到了别的窗口。** `vmrun start` 起的是 Workstation 主界面里的一个标签页，
按进程名找 `MainWindowHandle` 会拿到整个 Workstation 窗口；而且桌面上别的窗口
（比如正在跑 Codex 的终端）会盖在上面被一起截进去。得按窗口标题找 VMUIFrame，
并且截图前临时把窗口置顶。
