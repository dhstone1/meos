# MeOS

一个从零写起的最小操作系统。当前是**第三阶段**：传统 BIOS + MBR 引导，进 32 位保护模式，
自己驱动屏幕和键盘跑一个命令行，**并且自己实现了网卡驱动和一部分 TCP/IP 协议栈**——
PCI 枚举、e1000 驱动、ARP、IPv4、ICMP、UDP、DNS 全是手写的，没有借用任何现成库。

```
meos> ping baidu.com
resolving baidu.com ... 198.18.0.187
Pinging 198.18.0.187
Reply from 198.18.0.187: time=0ms
Reply from 198.18.0.187: time=0ms
Reply from 198.18.0.187: time=1ms
Reply from 198.18.0.187: time=0ms
packets: sent=4, received=4
meos> █
```

没有文件系统、没有内存管理、没有多任务。这一阶段证明的是「引导链路通了、保护模式进了、
中断收得到、显存能画、键能敲进去、包能发出去也收得回来」。

## 怎么构建

需要三样东西，都不大：

- **NASM**（汇编器）—— 装完确认 `nasm` 在 PATH 里
- **Python 3 + Pillow** —— 用来把系统字体渲染成点阵字模，并打包镜像
- **mkisofs** —— 打包 El Torito 可引导 ISO（VMware Workstation 自带一个）

```powershell
.\build.ps1                    # 构建
.\build.ps1 -Clean             # 先清空 build\ 再构建
.\build.ps1 -SelfTest          # 额外编一个开机自检版（见下文「调试手段」）
.\build.ps1 -Message "你好"    # 换横幅要显示的文字（会重新渲染字模）
```

产物都在 `build\` 下：

| 文件 | 说明 |
| --- | --- |
| `boot.bin` | 引导扇区，恰好 512 字节 |
| `payload.bin` | 内核载荷，被引导扇区装到物理地址 0x8000 |
| `meos.img` | 1.44MB 软盘镜像（BIOS 可直接引导） |
| `meos.iso` | El Torito 可引导光盘镜像，给 VMware 用 |
| `meos.vmx` | 配套的虚拟机配置 |

字模是构建时现烤的，落在 `src\kernel\` 下（`font.inc` 横幅、`ascii.inc` 命令行），
两个都由 `tools/genfont.py` 生成，不要手改。

## 怎么跑

```powershell
.\tools\vmtest.ps1 -Wait 12          # 启动虚拟机、截图、判读日志
.\tools\vmtest.ps1 -Wait 12 -Keep     # 同上，但跑完不关机
```

脚本会把虚拟机控制台窗口临时置顶再截图（桌面上别的窗口会挡住它），
然后去 `vmware.log` 里找 `PANIC`，告诉你虚拟机是活着还是崩了。

**要自己敲键盘的话**，先在那块虚拟机画面上点一下——VMware 不会自动把键盘交给客户机，
它的状态栏会提示「请在虚拟机内部单击或按 Ctrl+G」。点完就能打字了，
`Ctrl+Alt` 把键盘还回宿主机。
## 键盘怎么工作

一条链路，从上电到屏幕上出现字母：

```
8042 键盘控制器 → IRQ1 → 8259（已重映射到 INT 0x20 以上）→ INT 0x21 → kbd_isr
                                                                    ↓
                                          扫描码 → 查表 → 字符 → 环形缓冲
                                                                    ↓
                                        主循环取字符 → 行编辑 → 命令分发 → 终端渲染
```

几个刻意的选择：

- **只认扫描码集 1。** 8042 默认开着翻译，送到 CPU 的就是集 1（低 7 位键号，
  最高位表示松键，`0xE0` 前缀表示方向键那类扩展键）。两张 128 项的查表
  `kbd_map_lo` / `kbd_map_hi` 就是全部的秘密，Shift 切表，CapsLock 只翻字母。
- **中断里做的事越少越好。** ISR 只干三件：读端口 `0x60`、把字符塞进 64 字节的
  环形缓冲、给 8259 发 EOI。行编辑和命令分发都放在主循环——
  这样即使某条命令跑得慢，键盘也不会丢键。
- **译码单独成一个函数** `kbd_handle_scancode`。看起来是多余的抽象，其实是为了让
  开机自检能喂同一份代码，而不是另写一份副本（否则验了等于没验）。

## 文本终端

屏幕按 **16x24 像素**切成格子，800x600 正好 **50 列 x 25 行**。

格子尺寸是试出来的：8x16（经典 VGA 文字格）用 TTF 渲染，汉字的形被挤成一团；
16x16 的话 `g`、`y` 的下缘会被切掉。16x24 是能同时装下大写字母和下伸部的最小格子。

- **画字**：定位到格子 → 刷黑底 → 铺点阵。没有硬件滚动寄存器可用。
- **滚屏**：显存整体往上搬一个文字行，再把最后一行刷黑（`rep movsd`）。
- **折行**：写满第 50 列自动换行。
- **光标**：格子底部两行刷一条白杠，由 IRQ0 每 8 个节拍翻转一次（默认 18.2Hz，
  大约 0.44 秒闪一下）。顺便也证明了定时器中断是活的。

## 命令行

目前认得四条命令，够把输入链路跑通就行：

| 命令 | 效果 |
| --- | --- |
| `help` | 列出命令 |
| `ver` | 打印版本 |
| `echo <文字>` | 原样打回来 |
| `cls` | 清屏 |
| `net` | 打印本机 IP / 网关 / DNS / MAC / 链路状态 |
| `ping <域名或 IP>` | 解析域名然后发 4 个 ICMP echo |

退格能删，Tab 当空格，认不得的就回一句 `unknown command: xxx`。

## 网络怎么工作

从 PCI 枚举一路写到 DNS，全是手写的：

```
PCI 枚举（端口 0xCF8/0xCFC）找到 e1000
  → 复位、建收发环、升链路
    → ARP 问网关的 MAC
      → IPv4 + ICMP：ping
      → UDP + DNS：把域名换成 IP
```

### 网卡：e1000

VMware 的 `virtualDev = "e1000"` 报出来的其实是 **82545EM（8086:100F）**，
不是通常说的 82540EM（100E）。8254x 全家的寄存器接口是一样的，
所以代码里按**家族**匹配一张 ID 表，而不是只认一个号。

收发用**轮询**、不用中断：这一版图省事，也不会和键盘中断抢。每个方向一个描述符环：

| 环 | 位置 | 规模 |
| --- | --- | --- |
| 接收 | `NIC_RX_RING` | 32 个描述符，每个挂一块 2048 字节缓冲 |
| 发送 | `NIC_TX_RING` | 8 个描述符，共用 `NIC_TX_BUF` |

### 网络配置是写死的

对应 VMware 的 NAT 网段（VMnet8），在 `net.inc` 顶部：

| 项 | 值 | 来源 |
| --- | --- | --- |
| 本机 IP | 192.168.220.50 | 自己挑的，故意落在 DHCP 池（.128-.254）外面 |
| 网关 / DNS | 192.168.220.2 | `vmnetnat.conf` / `vmnetdhcp.conf` |
| 掩码 | 255.255.255.0 | 同上 |

**换机器或换网段要改这里。** 没做 DHCP——那是下一步的事。

### 三处容易翻车的字节序

- 协议头里的多字节字段（ethertype、oper、长度、校验和）都是**网络序（大端）**，
  小端机器上得存成字节反过来的样子。代码里一律"逐字节写"，避免绕晕。
- IP 地址反而简单：点分顺序（192,168,220,50）本身就是网络序，`mov [buf], eax` 就对了。
- 校验和有个好性质：一补数加法对字节序是对称的，所以直接按 16 位小端字求和、取反，
  写回去就是正确的网络序校验和。

### DNS

只做了够用的一点点：发一个 A 记录查询，从应答里抠出第一个 IPv4。

域名要编码成"长度前缀"格式（`baidu.com` → `05 62 61 69 64 75 03 63 6F 6D 00`），
应答里的名字可能带 `0xC0` 开头的压缩指针，跳过的时候不能按长度走。
UDP 校验和填 0（IPv4 允许）。

## 代码结构

```

src/kernel/kernel.asm  内核：16 位实模式准备环境 → 32 位保护模式 → 中断 → 终端 → 命令行
src/kernel/net.inc     网络：PCI 枚举、e1000 驱动、ARP / IPv4 / ICMP / UDP / DNS
src/kernel/font.inc    横幅点阵（自动生成，不要手改）
src/kernel/ascii.inc   命令行 ASCII 点阵（自动生成，不要手改）
tools/genfont.py       用 Pillow 把系统字体渲染成点阵字模
tools/mkfloppy.py      把引导扇区和内核拼成软盘镜像
tools/vmtest.ps1       启动虚拟机 + 截图 + 判读日志
tools/vmdiag.py        从 .vmem 里读内核写的诊断块
tools/verify_selftest.py  拿自检版的诊断数据，在宿主机把这台会话重算一遍对账
tools/preview.py       把截图转成终端可见的 ASCII 灰度图
tools/keys.txt         按键脚本样例（见「调试手段」里为什么现在用不上）
vm/meos.vmx            虚拟机配置模板
```

### 引导链路

```
BIOS → 读软盘第 0 扇区到 0x7C00 → 引导扇区用 INT 13h 把内核读到 0x8000
     → 跳 0x8000 → 内核 16 位阶段：开 A20、VBE 选并设置 800x600x32 模式、
       把帧缓冲参数写进参数块、建 GDT、置 CR0.PE → 32 位阶段：
       建 IDT（兜底门 + 键盘 / 定时器两个真门）、采硬件参数、找网卡（PCI + e1000 初始化）、
       清屏、顶部画中文横幅、重映射 8259、打提示符、PIT 调到 1000Hz、sti、
       解析网关 MAC → ping 网关 → 解析 baidu.com → ping 它（走完说明网络全通）
       → 命令行主循环
```

### 内存布局

| 地址 | 用途 |
| --- | --- |
| `0x0000-0x04FF` | 实模式中断向量表、BIOS 数据区（不动它） |
| `0x5000` / `0x5200` | VBE 信息块 / 模式信息块缓冲区 |
| `0x6000` | 参数块：帧缓冲地址、行跨度、分辨率、位深 |
| `0x6200-0x62EC` | 诊断块：执行阶段、SVGA 寄存器、显存自检、键盘与终端状态 |
| `0x7000-0x77FF` | 保护模式用 IDT（256 项） |
| `0x7C00` | 引导扇区 |
| `0x8000` | 内核载荷入口 |
| `0x7C000` | 内核栈顶 |
| `0x10000` | e1000 收发环和缓冲（32×2048 收 + 2048 发 + 2048 拼包） |
| `0xFEBC0000` | e1000 的 MMIO 寄存器（BAR0，由 PCI 枚举得到） |
| `0xE8000000` | VBE 线性帧缓冲（由 SVGA_REG_FB_START 确认） |
## 调试手段

这个项目最麻烦的地方在于：屏幕上什么都不对时，你没法知道是没画上去、画到别处去了、
画上去了但没显示出来，还是画上去了、也显示了、但键盘根本没收到键。所以留了三个后门。

**一、诊断块 + `.vmem`。** 虚拟机运行期间 VMware 会把客户机物理内存映射成
`build\<uuid>.vmem`，文件偏移就等于客户机物理地址。内核把中间结果一路写进 `0x6200`，
宿主机直接读出来：

```powershell
python tools\vmdiag.py
```

```text
  阶段    = 6  (中断已开，命令行长跑中)
  横幅包围盒读回白像素   = 2611  (期望 2611，= 字模置位数) OK
  定时器节拍     = 160   (在跑，IRQ0 没问题)
  键盘中断次数   = 0     (还没按过键)
  扫描码历史     = （空）  (最新在最前)
  整屏白像素数   = 2842  (自检用)
  终端网格       = 50 列 x 25 行  (每格 16x24)
  光标（列, 行）  = (6, 3)
```

「定时器节拍」这一项专门用来看 **IRQ0 到底响没响**。它要是 0，说明中断根本没通，
那就别往下查画字了。「扫描码历史」存最近 8 个原始扫描码——只看最后一个是不够的，
只有看到整串才分得清「没收到按键」和「收到了但译码不对」。

**二、显存自检。** 画完之后把显存读回来数白像素，和字模的置位数对。
数出来对得上，说明显存里的画是对的，问题只可能在显示刷新那一段；
是 0，说明根本没画上去。这一招能一刀切开两类完全不同的故障——
上次那个把 VMware 写崩的 bug 就是被它定位的。

普通构建在打完提示符后会做一次整屏自检（横幅 2611 + 提示符 231 = 2842）。

**三、开机自检 + 宿主机对账。** `-SelfTest` 版会在开机时把一串预置扫描码
**喂进和真键盘中断完全同一个译码函数**，把 `help` / `echo typing works` /
`MeOS 1234` / `ver` 四行"打"一遍，然后数一遍整屏白像素。宿主机这边：

```powershell
python tools\verify_selftest.py
```

它从 `kernel.asm` 里读回扫描码流、键盘码表、提示符和各条命令的输出字符串
（不另抄一份，否则改了一处忘了另一处，验证就成了摆设），把同一场会话按同样的
换行 / 折行 / 滚屏规则重放一遍，算出期望的白像素数，再逐行和内核数的对：

```text
逐行对账（行: 期望 / 实际 / 差）：
   0:   418 /   418        横幅
   1:  2193 /  2193        横幅
   3:   454 /   454        meos> help
   ...
  逐行核对：全部对上
宿主机重算期望 = 10434
内核数出来的   = 10434
结果：完全一致，显存里一个像素都不差
```

**为什么要费这个劲**：VMware 会丢掉一切宿主侧合成的按键（见下面第 6 条），
自动化测试没法真的"敲键盘"。自检走的是真代码，所以它验的是真东西；
真键盘那一段则由「键盘中断次数」这一项兜底——按下键它就会涨。

## 踩过的坑

**1. PCI 设备 ID 别只认一个型号。** VMware 的 `virtualDev = "e1000"` 报的是 82545EM（100F），
不是 82540EM（100E），只 `cmp eax, 0x100E` 的话一辈子也找不到网卡。
**教训：按家族匹配一张表。**

**2. 诊断块里混了非 dword 字段，就别按一串 dword 解包。** MAC 是 6 字节 + 2 字节填充，
`vmdiag.py` 原来用 `struct.unpack("<18I")` 连续解，从 MAC 开始整体错位，
把一个计数器读成了 41 亿多。
**教训：按绝对偏移逐个读。**

**3. 长度驱动的循环，先判零。** DNS 域名长度忘了设置就是 0，
拷贝循环的 `dec ecx / jnz` 从 0 绕成 `0xFFFFFFFF`，变成四十亿次的失控写内存，
内核当场卡死在启动阶段（进度停在 7，连 DNS 包都没发出去）。
**教训：`dec` + `jnz` 的循环，入口处必须挡住 0。**

**4. 「只做一件事」的小工具函数，也要守住调用约定。** `con_crlf` 为了换行把 `AL` 设成 13，
却没保护 `EAX`。调用方刚解析出来的 IP 紧跟一句换行，首字节 198 就被回车符覆盖成 13，
ping 打到了 `13.18.0.187`，四个包一个回应都没有。
**教训：辅助函数一样要保护寄存器，别指望调用方记得。**

**5. 协议字段的字节个数要数准。** `05"baidu"03"com"00` 是 **11** 字节，我写成 13，
多拷 2 字节垃圾把 QTYPE 挤错位，服务器回了个「没有答案」的转介。
能查出来是因为把收到的帧前 64 字节直接 dump 进了诊断块，
和宿主机发的同样查询一比就现形了。

**6. 参数块读错了地址，把 VMware 写崩了。** 16 位阶段把参数写进 `0x6000`，
但 32 位阶段读的是 `[P_FB]`——而 `P_FB` 只是个偏移量（0x00），
于是实际读的是物理地址 `0x0000` 的**实模式中断向量表**。清屏时拿这套垃圾参数
算出天文数字的长度，`rep stosd` 一口气刷了几百 MB 物理内存，路上正好盖住
VMware 给 SVGA 的 MMIO 空间，虚拟机当场报
`iospace_shared.h:479 VERIFY` 不可恢复错误。
**教训：跨阶段共享的结构，访问时必须写全基址。**

**7. `shl eax, 1` 取不到字节的最高位。** 画点阵时用 `shl` 把像素位移进进位标志，
写成 `shl eax, 1` 的话进位来自 bit31，而 `EAX` 只有 8 位有效数据，
结果一个像素都不会画。必须是 `shl al, 1`。
**教训：操作数是几位，就用几位的移位。**

**8. 保护模式没有 IDT 就是三重故障。** 异常没人接 → 三重故障 → VMware 直接复位
虚拟机，现象和「虚拟机自己重启了」一模一样，极难排查。内核里装了一张
256 项全指向同一个兜底处理程序的 IDT，出事至少能停在原地。

**9. `cli; hlt` 会让 VMware 判定「客户机操作系统已禁用 CPU」。** 得先把 8259 的
中断全屏蔽，再 `sti`，CPU 才能真正安静地歇在 `hlt` 上。这一阶段有了 IRQ0 定时器，
空转用 `hlt` 反而是对的——中断开着，按一个键或者来一个节拍就会醒。

**10. 截图截到了别的窗口。** `vmrun start` 起的是 Workstation 主界面里的一个标签页，
按进程名找 `MainWindowHandle` 会拿到整个 Workstation 窗口；而且桌面上别的窗口
（比如正在跑 Codex 的终端）会盖在上面被一起截进去。得按窗口标题找 VMUIFrame，
并且截图前临时把窗口置顶。

**11. VMware 会丢掉一切宿主侧合成的按键。** 想在宿主机上脚本化地"敲键盘"，
这几条路全试过、全不通：`SendKeys`（0 个扫描码进客户机）、
`keybd_event` 直接发硬件扫描码（还是 0）、`PostMessage(WM_KEYDOWN)` 给控制台窗口
（依然是 0）。VMware 是在很底层把注入的输入滤掉了。所以验证键盘只能靠自检
（见上面第三条），或者人肉敲。

**12. 键盘得"点进去"才算交给客户机。** VMware 不会自动把键盘给客户机，得先在
虚拟机画面上单击，或者按 `Ctrl+G`；`Ctrl+Alt` 还回来。
坑在于**第一次点击往往只是把窗口激活**，进不去客户机——所以脚本里点完要读
一下状态栏，看到「要返回到您的计算机，请按 Ctrl+Alt」才算真抓到了。

**13. 光标横杠会留在原地。** `con_newline` 只管把位置挪到下一行，它不碰光标——
光标是 `con_putc` 的事。命令行的回车和命令输出一开始直接调 `con_newline`，
结果每次换行都在上一行末尾留下一条 16x2 的白杠，自己看屏幕不太明显。
是自检版的逐行像素对账把它揪出来的：**每行正好多 32 个像素，8 行就是
4 条命令 × 2 次换行**。修法是给上层加一个会管光标的 `con_crlf`。
**教训：底层原语不负责的事，上层不能想当然。**
