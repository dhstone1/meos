### FS4 验收证据链（最强一档）

1. **verify_selftest.py**：自检流回放 `cp /hello.txt /hd/c1.txt` →
   `cat /hd/c1.txt` → `ls /hd`，25 行像素 **19792=19792 一个不差**
   （期望屏由回放器自己的 `_e2_walk` 走查模型生成，含 lost+found）。
2. **verify_ext2.py live**（VM 运行中）：STAGE=6 / ERR=0 / INO=16 /
   FREE=8148（真值 8149 − 1）/ D_EXVEC=0（全程无 CPU 异常）。
3. **verify_ext2.py disk**（关机后）：c1.txt ino=16 / mode 0x81A4 /
   links=1 / size=73 / blk=43、块位图 bit42、inode 位图 bit15、
   超块 free 计数、根目录游走 end==1024（无 rec_len 洞）。
4. **e2fsck 双 clean**：全新镜像与运行时写过的盘（拷出 hd-flat.vmdk）
   均通过 `e2fsck 1.47.3 -fn`，0 报错 EXIT=0（16/256 files, 44/8192 blocks）。
5. **二启幂等**：同一块盘不重建，二次开机重放整条流——像素不变、
   FREE 停在 8148 不再降（截断复用生效，无重复分配）。

powershell -ExecutionPolicy Bypass -File build.ps1 -SelfTest

## 六、本工程沉淀的硬教训（全文见技术文档 §14）

- **踩坑 28（最贵的一课）**：工具链自洽 ≠ 格式标准。块位图 **bit i ↔
  块 i+1**（first_data_block=1 移位，位号不能直接当块号）；inode 偏移
  i_size@0x04 / i_links@0x1A 本来就对，"凭记忆对齐"改成 0x08/0x02 是
  把对的改错——三方工具全绿掩盖了它，最终靠 e2fsck 揭穿并整体回滚。
- **idt 向量记录器**（踩坑 25 的产物，保留为正式设施）：call 目标寄存器
  被参数装载撞掉 → call 0 → #UD → 中断存根挂死，黑屏下唯一线索是
  D_EXVEC=0x0A。今后内核异常先看它。
- 其余 26 条见技术文档 §14.1（含 cmp 宽度跟声明走、selftest_len 差 1、
  探存在失败后清错误码、dir_insert 的 rec 吃满块尾等）。
