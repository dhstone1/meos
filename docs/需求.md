# MeOS 需求说明

## 一句话目标

做一个能在 VMware 里引导起来的最小操作系统：开机在屏幕上打出问候语，
然后给一个**敲得进英文的命令行**。

```
Hi，我是meos，很高兴来到这个世界~

meos> echo typing works
typing works
meos> _
```

## 第一阶段（已完成）

BIOS + MBR 引导，进入 32 位保护模式，在 800x600 图形模式下居中打印一行中文后停机。

| 项 | 标准 |
| --- | --- |
| 跑在哪 | VMware Workstation 虚拟机，x86 架构，BIOS 固件 |
| 怎么起 | 传统 BIOS + MBR 引导，光盘挂载启动，不用 UEFI、不用 GRUB |
| 看到什么 | 800x600 图形模式下，屏幕正中一行中文，白字黑底 |
| 之后怎样 | 停机保持画面，不重启、不报错 |
| 门槛 | **能看到这行字就算过**，不要求装到虚拟硬盘、不要求交互 |

## 第二阶段（本轮）：键盘 + 命令行

### 验收标准

| 项 | 标准 |
| --- | --- |
| 键盘 | PS/2 键盘，按下能在屏幕上看到对应字符 |
| 输入 | 英文可打印字符（0x20..0x7E）、回车、退格、Tab、Shift、CapsLock |
| 编辑 | 退格能删掉行尾字符，屏幕上同步擦掉 |
| 提交 | 回车把这一行交给命令分发，然后打新提示符 |
| 输出 | 能打印多行；写满一行自动折行；写满一屏自动滚屏 |
| 光标 | 有一个会闪的光标，提示当前输入位置 |
| 命令 | `help` / `ver` / `echo <文字>` / `cls` 四条，认不得的回 `unknown command: xxx` |
| 停机 | 不再"停机"——系统保持运行，随时可以继续输入 |

### 明确不做的事

- 不做中文输入（只支持 ASCII；横幅那个中文是烤好的点阵，不是输入）
- 不做方向键、Home/End、Delete、翻页、历史命令
- 不做鼠标
- 不做管道、重定向、参数解析框架
- 不做文件系统、多任务、内存分页（留给第三阶段）

### 技术选型

| 选择 | 理由 |
| --- | --- |
| PS/2 键盘 + 扫描码集 1 | 8042 默认就开着翻译，拿到的就是集 1，查表最简单 |
| 8259 重映射到 0x20 以上 | 默认的 IRQ0..7 映射到 INT 08h..0Fh，压着 CPU 异常向量 |
| IRQ0 定时器 | 光标闪烁要节拍；顺便也是「中断通了没有」的探针 |
| 16x24 点阵格子 | 800x600 正好 50x25；试过 8x16（太挤）和 16x16（下伸部被切） |
| 中断只塞缓冲，处理放主循环 | 命令跑得慢也不会丢键 |
| 自渲染 ASCII 字模 | 系统没有字库，和中文横幅走同一套 Pillow 流程 |

## 运行环境

- VMware Workstation 17.6，`mkisofs.exe` 直接用它自带的
- NASM 汇编器
- Python 3 + Pillow（渲染字模、打包镜像、验证）
- 开发机是 Windows + PowerShell

## 交付物


## 验证方式

屏幕类的东西好验：截个图，再用显存自检把"该画多少像素"和"实际画了多少像素"
对一遍，就能确定是画错了还是没显示。

**键盘类的东西不好验**：VMware 会丢掉一切宿主侧合成的按键——`SendKeys`、
直接发硬件扫描码的 `keybd_event`、给控制台窗口 `PostMessage` 全试过，
一个扫描码都进不了客户机。所以键盘链路分两段验：

- **宿主侧没法自动化的那一段**（真键盘 → 8042 → IRQ1）：按下键，
  诊断块里的「键盘中断次数」就会涨；这个数字本身就是证据。
- **其余全部**（译码 → 环形缓冲 → 行编辑 → 命令分发 → 终端渲染 → 折行 → 滚屏）：
  由 `-SelfTest` 版把预置扫描码喂进**和中断同一个译码函数**跑一遍，
  宿主机再用 `tools\verify_selftest.py` 把同一场会话重算一遍逐行对账。

## 无歧义确认过的点

- 「系统能够安装」在本阶段解释为「能挂载 ISO 引导并跑起来」，不要求写入虚拟硬盘
- 「界面提示」在本阶段就是屏幕上的一行字，不要求图形界面框架
- 「支持英文输入」= ASCII 可打印字符 + 回车/退格/Tab/Shift/CapsLock，不含中文输入法
- 系统不再停机，而是常驻命令行
- 验证以「能自动复现的证据」为准，不靠"我看着屏幕上好像有字"
